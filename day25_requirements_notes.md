# Day 25 Requirements Notes

Day 25 is Strategic Scenario Simulation & Path Comparison v2. Extend the existing Scenario Intelligence implementation; do not create a duplicate scenario, forecasting, decision, alert, outcome, or scoring engine. Scenario paths are decision support only and must not execute financial actions, change pricing, spend money, contact customers, send email, or modify production systems.

Scenario path types may include BASELINE, GROWTH, DEFENSIVE, INVESTMENT, COST_REDUCTION, COMPETITIVE_RESPONSE, OPPORTUNITY_EXPANSION, and CUSTOM, while remaining extensible. Each scenario should expose assumptions with VALIDATED, INVALIDATED, UNTESTED, or UNKNOWN status; directional impacts using POSITIVE, NEGATIVE, MIXED, NEUTRAL, or UNKNOWN; affected metrics and expected directions; risks and potential upside linked to existing intelligence; strategic fit; trajectory alignment; relevant cross-signal context; expected outcome; historical analogues when evidence exists; uncertainty; and an explanation covering why it exists, support, failure modes, invalidation conditions, expectations, and unknowns.

Every comparison must include a BASELINE representing continuation of current trajectory/strategy without invented numerical future values. Compare up to three paths. Scorecards are structured, deterministic, explainable, and should avoid false precision. Reuse existing strategy, trajectory, cross-signal, decision, outcome, monitoring, and learning context. Selecting a scenario creates or reuses a reviewable Decision draft; it must not auto-execute. Scenario lifecycle: DRAFT, ACTIVE, UNDER_REVIEW, SELECTED, COMPLETED, INVALIDATED, ARCHIVED. Preserve scenario history. Critical assumption changes should mark a scenario at risk/under review rather than silently deleting or changing it.

Required protected API capabilities include scenario path summary/list, create/update, comparison up to three scenarios, detail/evidence/history, refresh/assumption review, lifecycle transitions, and use-this-scenario-to-create/reuse a decision draft. UI adds a concise STRATEGIC PATHS area/card and evidence-heavy detail/comparison views, reusing the existing design system and DashboardV2 patterns. AI is optional for explanation only; deterministic structured data remains authoritative.

Verification: deterministic unit, persistence, lifecycle/history, tenant-isolation, comparison, and decision-draft tests; TypeScript checks; full test suite; production build; save Day 25 checkpoint and stop before Day 26.
